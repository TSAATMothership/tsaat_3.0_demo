# UI design contract

Use the discovery/risk-profile dark blue and cyan theme, compact panel headings and consistent explanatory scope text. The workspace header owns security domain, network/system selection, date and Menu; account identity and Logout controls are removed. The workspace opens directly without a login screen. Do not restore removed page-wide filter blocks on Measures, Findings or Briefs & Reports.

Governance is the first sidebar group. Overview, Trends and Insights use normal keyboard-accessible links, active-page highlighting and group collapse behavior. Overview and Trends remain heading-only placeholders. Insights is a continuous vertical executive infographic: local TSAAT branding and original terrain SVG, a scope/snapshot masthead, four headline measures, anchored visibility/exposure/service/resilience/priority chapters and expandable evidence definitions. Large numbers, coverage rings, tool cards, severity bars and a service-association flow all have textual equivalents. Cards stack on narrow screens; the workspace owns scrolling. Header scope, dates and security domains follow every evidence link. Empty scope retains the standard blank workspace; missing evidence and failed reads have distinct states. See the [Insights contract](../Requirements%20Documentation/15-Governance-Insights.md).

Insights includes a **Generate PDF** masthead action that wraps with the snapshot edition on narrow screens. It announces progress, disables repeat activation and shows a retryable inline error. The downloaded A4 infographic uses white backgrounds, navy/mint branding, vector charts and deliberate chapter breaks for clean printing. Its cover records scope, domains, selected snapshot date, the recorded snapshot timestamp and a separately labelled export time; timestamp and page number repeat in each footer. Long labels/tool lists flow to continuation pages without truncation.

## Tables

Use FindingsDataTable and ExplorerColumn definitions for shared search, facets, numeric ranges, sorting, matching counts and empty states. Buttons open in-place details; anchors navigate. Network/ICT explorers use scrollable unpaginated tables. All row drill-throughs are native links with target=_blank and rel=noopener noreferrer, with accessible names announcing the new tab. Names open the existing entity-details panel in the destination tab; counts and coverage links preselect the row, actual snapshot and matching severity/duration/view. The originating table retains its filters, order and focus. CMDB keeps searchable field/value rows with plain headers. KPI/SPI result pills have consistent widths and report links fit on one line.

## Dialogs and panels

Use native dialogs for focus containment and modal layering. `settings-popup` defines Settings dimensions: 150px desktop margins, 16px at the existing small-screen/short-height breakpoint. Shared asset compliance uses that class and WorkspaceTabs. Entity and finding details use the existing right-hand measure-scope panel styles. CMDB opens from the left at min(44.8rem, 76.8vw), 20% narrower than its former min(56rem, 96vw) width, with a right border/shadow and a left-entry/exit transition. Reduced motion remains supported.

Service Impact's Explore selection opens an Impact graph using the same settings-popup class; Scope & Selection remains on the page and there is no Explore the Impact tab. Inspired by [Neo4j Bloom's graph scene](https://neo4j.com/docs/bloom-user-guide/current/bloom-visual-tour/bloom-overview/), coloured category nodes, labelled connections, a search field and a node inspector expose recorded service/system/device relationships. Risk rings and finding badges supplement category colour with text/counts. Search includes collapsed nodes, and scene limits are explicitly disclosed. Selecting a node highlights its neighbours; connection focus, system expansion, drag/pan, zoom and Fit graph support exploration without changing the analysis totals or header scope. Keyboard users can select SVG nodes with Enter/Space, pan the focused graph with arrow keys, zoom with +/−, reset with 0, and navigate connections through ordinary buttons. The inspector stacks under the graph on narrow/short viewports. Native dialog focus containment, Escape and focus return apply, including nested finding details.

Risk controls sit above the graph: a severity checklist, paired inclusive Min/Max sliders with numeric equivalents, and Reset risk filters. Counts combine the chosen severities per node. Opening the graph or resetting its filters selects Critical Exposure and High Risk with Min 1. Select all starts at Min 0; a subset starts at Min 1, which can be changed explicitly. The checklist keeps configured labels and closes on Escape before the graph does. Filtered totals/search/details update together, and empty results retain controls and a reset action. The popup opens in Hierarchical layout with Top down direction. Layout controls offer Force-Directed, four Hierarchical directions, Circular/Radial, and generated Coordinate/Spatial positions; selected spatial nodes have X/Y fields. The layout families take inspiration from [NeoDash's graph layouts](https://neo4j.com/labs/neodash/2.4/user-guide/reports/graph/) and [NVL's layout types](https://neo4j.com/docs/api/nvl/current/types/_neo4j_nvl_base.Layout.html). One animation clock moves nodes and attached edges over 650ms with eased interpolation, including interruption handling and reduced-motion support. Coordinate generation and editing are local to the popup and are explicitly distinguished from geography. Controls wrap and the graph/inspector scroll vertically on narrow or short windows without changing Settings popup dimensions.

Return focus to the invoking control. Escape closes a filter menu before an inner detail, then the main dialog. Include loading, error/Retry and empty states. Evidence and remediation remain available without clipped text.

The Impact graph control bar uses two aligned cards: Filters and Layout & view. Filters keeps the severity dropdown, paired Min/Max rows and reset together; its caption names the severities being counted and the maximum for one node. A full-width Expand all affected CIs / Collapse all affected CIs button sits below severity, with native keyboard activation and an aria-pressed state reflecting system expansion. It leaves connection focus and fits the scene without changing risk filters, and is disabled when no CIs match. Layout & view groups layout variants with zoom and Fit graph. Focus connections / Show scope is anchored at the top-right of the graph canvas on desktop and narrow screens, above the graph interaction layer; it remains disabled until a node is selected. Labels, select heights, number fields and spacing align; groups stack below 1200px and fields stack on phones. The popup scrolls vertically on narrow/short screens while retaining Settings dimensions. Node badges show exact matching counts rather than a 99+ cap; the inspector shows matching findings and only the selected severity breakdown. Dropdown counts explicitly refer to findings across the scope, distinct from the per-node range.

The CMDB panel retains its read-only details, close/Escape/focus return and error/Retry interactions. Service Impact device links keep the findings panel mounted beneath CMDB, preserving its active tab, search/filters, scroll and expanded evidence. CMDB is the top native modal; closing it returns focus to the invoking device without closing findings or the graph. The retired Network Impact Analyser launch button is removed. Old analyser bookmarks return to the risk profile matching their header scope.

ICT System Dependencies has its own workspace page beneath ICT System Impact Analyser in Cyber Security, with an independent system selector and Run action. It opens with Production selected and retains that selection for empty results; users can choose All explicitly. ICT System Impact Analyser opens with Critical Exposure and High Risk selected. The dependency diagram no longer overlays the risk diagram. Diagram titles and filter controls wrap on narrow screens so environment, severity and export controls remain reachable. Both pages keep the existing scope/date, keyboard, error/Retry, export and drill-through patterns.

## Charts

Impact graph node selection retains camera zoom and pan for pointer/keyboard selection, search results and connected-node links. Fit graph and the 0 key explicitly reset the view. Existing layout, filter, expansion and connection-focus actions retain their scene-fitting behavior.

Compliance is green, non-compliance red and unknown orange, with visible numbers/text. Severity colors are Critical Exposure red, High Risk orange, Major yellow, Moderate blue and Data Gap purple. Summary exception lists scroll after approximately five rows and retain total compliance bars when no exceptions appear.

Device/SPI heatmaps default to 40px cells, support resizing, search and status filters, group devices by result and place the highest SPI severity at the right. Zero observations must not be presented as 100% compliance.

## Accessibility and responsive acceptance

Tabs support Arrow keys and Home/End with aria-selected/controls. Controls have labels and visible focus. Long names/evidence wrap or scroll inside their region; tables can scroll horizontally without overflowing the viewport. Verify desktop and a 390px viewport, keyboard traversal, layering, focus return and loading/error/empty states.

Shared implementation: FindingsDataTable, FilterHeader, WorkspaceTabs, SettingsPopup, ServerComplianceView, RiskEntityDetailsPanel, ComplianceHeatmap and app/globals.css. Update this contract when shared interactions change.

## Shared SQL and No-SQL interface

Discovery Overview now places vulnerability and server patch panels below six headline findings, preserving its tool coverage and inventory panels. Counts link to matching explorer rows using native anchors with visible keyboard focus and the resolved scope/date. Severity and patch status remain explicit text; redundant demo-data notices are omitted. Unknown patch evidence is visible rather than counted as healthy, and no-server scopes show N/A. Cards use three columns on wide layouts, two on narrower layouts and one where needed; the security panels stack below 820px of content width. Patch drill-through filters initialize the posture tab and survive switching away and back.

Patch Management Explorer follows End Point Explorer's hero, four interactive bar-chart cards and bounded table with the same toolbar/cell/pagination spacing. Scope-wide verified and overdue figures stay in the hero. WorkspaceTabs sit beside the chart caption on desktop and select Patch posture, Restart & evidence and Planning & ownership; each retains independent search, chart/column selections and ranges and shares canonical full-field export. Text-labelled status pills distinguish patched, failed, restart and unknown states without relying on color alone. A native details disclosure retains evidence/export guidance below the table, without a demo-data notice. The table fills remaining desktop space with internal scrolling and uses End Point Explorer's 34rem body cap below 1250px. Charts stack and tabs wrap on narrow screens. CMDB device controls retain the global modal and impact-window action. See [the patch feature contract](patch-management-explorer.md).

Both artifacts render the same workspace, URL navigation, scope/date filters, tables, dialogs and reports. No-SQL replaces the Database Settings tab with JSON Data Files, showing the server store path, snapshot inventory and persistence explanation. Password, SPI risk, SPI priority and discovery editors remain available. Their saves persist on the server across browser sessions and restarts. Apply desktop, narrow-layout, keyboard and loading/error-state checks to both builds. See [data providers](data-providers.md).

Security Vulnerability Explorer uses the same End Point Explorer layout and table sizing as Patch Management Explorer. Four SummaryChart cards cover severity, software, source and OS; scope-wide CVE/endpoint/missing-date totals remain labelled in the hero. Both pages use FindingsDataTable's optional chart summaries, which share its facet calculations and filter state; keyboard-operated bars toggle selections, reset pagination and update filter chips/export. Other FindingsDataTable consumers keep their existing layout. Native column-filter popovers, endpoint CMDB dialogs and loading/error boundaries remain. Long descriptions/actions wrap within the horizontally scrolling table. Its export retains an actionable error. See [the feature contract](security-vulnerability-explorer.md).


The header begins with a Security Domain multi-select: PROTECTED, SECRET and UNKNOWN, all selected by default. It uses the existing staged Update, search, Select All, clear, Escape/focus-return and responsive popover patterns. Domain changes retain network/system and snapshot selections; selected entities stay available to clear even if their model domain is outside the new selection. End Point Explorer includes Security Domain in its table/export; model rows and drill-through details show it.

Select All remains focusable with aria-disabled after selecting every option. This avoids closing the popover through a disabled-control blur before the user can press Update. The production smoke test verifies the none-to-all sequence and Escape focus return.


Discovery Overview places Download overview PDF beside the snapshot. The button has busy/error states and keyboard support. The PDF follows the existing navy/cyan report template, with six headline cards, three-column discovery-tool report cards, chart/table sections, full labels in supporting tables and page-numbered continuations.

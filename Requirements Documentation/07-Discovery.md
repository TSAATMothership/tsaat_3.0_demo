# Discovery workspace

Life Cycle Management follows Patch Management Explorer, highlighting servers with overlapping expired warranties, unsupported software and OS at N-2 or older. Hardware, software and OS registers expose the evidence and unknowns. Scope/snapshot and Personas controls apply. See [lifecycle rules and priority order](16-Life-Cycle-Management.md).

Current contract: TSAAT UI 3 baseline, 2026-11-03. Maintain with related source changes; see [SDLC](../docs/sdlc.md).

Current sidebar views are Discovery Tool Coverage, Discovery Compliance Explorer, End Point Explorer, Installed Software Explorer, Security Vulnerability Explorer, Patch Management Explorer, Life Cycle Management, Shadow IT Explorer and Topology Explorer. They share applied header scope and snapshot. Target State Analyser is not a navigation page; compatibility report/template APIs may remain.

Discovery Tool Coverage and Discovery Compliance Explorer have no page-level Environment or Asset Type controls or empty filter row. Their shared header scope/date controls and table search/facets remain available. Existing bookmarked query parameters and provider filtering remain compatible.

Topology Explorer follows Shadow IT Explorer, providing combined name/software/CVE/IP lookup for endpoint and model CIs. Endpoint paths trace upstream to services and capabilities; model CIs show downstream systems and networks. See [path meaning, scope and interaction contract](20-Topology-Explorer.md).

Installed Software Dashboard is not a sidebar destination; its existing URL remains available for bookmarks. The former Software Insights tab is now the standalone Installed Software Insights page in Governance below Cyber Terrain Insights, retaining its PDF export. Scoped installation/product/endpoint counts, version variation, discovery age and evidence completeness lead to matching Explorer records. See [count definitions, briefing and interaction contract](18-Installed-Software-Insights.md).

Security Vulnerability Explorer follows Installed Software Explorer and maps CVE code, name, description, detection date, CVE creation/reservation date and remediation action to the same endpoint/OS context. It also shows affected software/version and evidence source. Search, column facets, pagination, CMDB links and filtered Excel export use shared patterns. Unknown metadata stays Not recorded. Public CVE mappings use exact reviewed installed versions and visibly distinguish inferred sample exposure from scanner observations. See the [feature, provenance and rollout contract](../docs/security-vulnerability-explorer.md).

Overview summarizes scoped discovery. Tool coverage combines configured tool applicability and stored detection evidence; missing, covered and unavailable values remain distinct. Tool-owned asset drill-through uses the same snapshot. Discovery Compliance Explorer follows Installed Software Explorer's interface: a scope-total/snapshot hero, four shared interactive chart cards, matching search/export controls, active-filter chips, column facets and a bounded scrolling table with pagination and CMDB device links. Charts cover compliance, missing discovery tools, discovery sources and recorded UTC discovery dates. They select the existing column filters, support multiple values and retain all other filters in their counts. Missing-tool counts can overlap across CIs; None denotes no recorded missing tool. Tool-check coverage for matching rows remains visible beside the matching count. The removed page-level Environment/Asset Type controls remain absent; their existing table columns are retained. Empty evidence and export errors use the existing explicit states.

Overview also summarizes Security Vulnerability Explorer and Patch Management Explorer using their existing facade operations, pinned to the resolved snapshot. Six headline links cover critical/high CVE observations, overdue server patch actions and the four existing discovery checks. Separate panels show observation totals, distinct CVE codes, affected endpoints, source severity, missing remediation, all six patch states and the percentage of scoped servers verified Patched. Unknown servers remain in that percentage's denominator; an empty server scope shows N/A. Suggested actions include severe CVE review, overdue patch work and unknown evidence alongside the existing discovery actions.

Every observation/status/deadline count links to matching explorer filters with only the shared network/system scope and actual snapshot. Vulnerability severity and remediation filters use the explorer's display normalization; overdue patches use `daysOverdue >= 1`. Patch links initialize the posture tab through validated `discoveryFilters`, including numeric ranges, and retain those filters when switching tabs or exporting. Invalid/oversized filters fall back to an unfiltered explorer. Browser checks compare linked counts under network and historical system scopes, keyboard navigation, empty scopes and a 390px viewport.

Overview counts are observations rather than open remediation cases. No observations do not establish absence of vulnerabilities; the demo omits repeated sample-data notices while preserving recorded evidence-source fields. Patch status/overdue logic is reused without inferring patch requirements from CVEs or changing discovery compliance, configurable measures, schema, stored data or existing reports.

Patch Management Explorer follows Security Vulnerability Explorer. One row per server tracks patched/not-patched/failed/in-progress/restart/unknown status, installation and last restart dates, installed/target patch levels, missing updates, due dates and evidence validity. Three keyboard-accessible views separate posture, restart/evidence and planning/ownership with per-tab search/facets/ranges, CMDB impact navigation and canonical Excel export. Current affirmative evidence is required for Patched; stale/incomplete evidence stays Unknown and active exceptions do not suppress overdue actions. SQL and JSON share the same snapshot-relative derivation. See [status, best-practice sources and migration contract](../docs/patch-management-explorer.md).

End Point Explorer uses canonical asset identity, IP, model, discovery timestamp/source and asset type. Installed Software Explorer groups the current software inventory and supports its scoped export. Shadow IT Explorer uses its dedicated SQL source/definitions and supports scoped export. Export handlers reapply relevant filters and return canonical data, not an independent unscoped extract.

Security Vulnerability Explorer and Patch Management Explorer follow End Point Explorer's visual layout: scope/date hero, four interactive bar-chart summaries, matching table controls/row spacing and a bounded scrolling results panel. Patch tabs retain their own chart, search, facet and range selections. Chart bars share column filters with the table and export; counts respect all other filters. Scope totals remain explicitly labelled. Desktop tables use remaining panel height rather than the height of all rows, and narrower layouts use the same 34rem table-body cap as End Point Explorer. Evidence, status rules and all existing fields remain available; repeated demo-data notices are omitted.

CMDB opens from device names. Explore Topology opens the loaded CI in Topology Explorer with the originating scope/domains and resolved snapshot. It is disabled while details are unavailable or the active persona disables that page. Its searchable Field/Value table has plain labels rather than interactive headers. Per-type SQL mappings govern which approved attributes appear; the seven types initially share 18 fields. CI owner/change assignment/incident assignment display fields are retired; network/system operational owners remain separate.

No-SQL sample stores populate endpoint IP/MAC/model/discovery fields and installed-software paths, discovery metadata and host patch labels. Imported SQL values remain authoritative. Shadow IT includes both IP Scan and ARP observations; selecting an ICT system includes ARP nodes through their owner in the same snapshot/network, matching SQL. Known endpoints are audited for nonblank MAC addresses and device models across every snapshot. Unidentified nodes must not receive invented endpoint identity or OS/software attributes. Explicit finding coverage repair excludes those Shadow IT nodes and does not change applicability.

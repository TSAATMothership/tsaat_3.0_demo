It opens the former Software Insights briefing directly, including Generate PDF. **Installed Software Dashboard** has no sidebar link and remains accessible through the existing `/discovery-coverage?discoveryView=installed-software-insights` URL for bookmark compatibility. The printable A4 briefing matches the Governance page with the actual TSAAT logo, its local software-terrain illustration, package/layers/endpoint icons, navy mastheads, mint accents and light evidence cards. ## Count definitions and limits

- Each Explorer row is one installation; repeated installations on the same endpoint remain separate. Endpoint counts deduplicate by asset ID, not display name. Endpoints with no software inventory are excluded, so this is not overall endpoint coverage.
- Product and version names use the Explorer's trimmed recorded values, without merging spelling/case variants. Missing names are excluded from named-product counts and concentration, but their installations remain in the overall denominator. Multiple versions means at least two distinct non-missing versions for a named product. Missing versions are excluded from variation.
- Version completeness is installations with a recorded version divided by all installations. No records means no denominator, never 100% assurance. Counts are inventory evidence, not licences, support status, version currency or CVE findings.
- Discovery age reuses Explorer logic relative to the resolved snapshot: last 7 days, 8–30, 31–90, over 90, after snapshot and missing/invalid date. Stale means over 30 days; future and undated records remain separate. Evidence-gap counts overlap.
- Top lists use descending counts with name tie-breaks; variation uses descending distinct versions, then installations, then name. Unknown values remain visible in OS/source charts.

## Data, access and validation

Both pages call `loadInstalledSoftwareExplorerData` through `lib/data-loader.ts` and summarize its already scoped rows in `lib/installed-software-insights.ts`. SQL's scoped installation query and JSON's inventory projection remain unchanged. Neither page reads a separate dataset or stores a new field. No SQL migration, JSON upgrade, seed change or calculation-contract checksum update is required. The existing application access model and Explorer compatibility route remain intact.

The dashboard retains its existing `discovery-software-insights` persona preference. The Governance briefing has the separate `governance-software-insights` preference, included in new/default configurations. Existing saved version-2 selections stay unchanged; enable the new Governance page explicitly in Settings > Personas when needed. No preference is silently granted during a read.

Empty records show an explicit no-evidence state on either page; failed loading shows an alert and scoped retry, never zero metrics. The workspace owns vertical scrolling; hero, cards and metrics reflow at narrow widths. Sidebar links and chapter anchors support keyboard navigation and visible focus, and chart values are available without hover or colour interpretation. Existing workspace loading feedback applies.

Navigation/presentation changes require focused render, link-count reconciliation, sidebar/persona/keyboard/anchor and narrow-layout checks, including regression checks for the shared Cyber Terrain styles. Provider validation is required when data/provider behavior changes, as described in the SDLC. The original feature validation covers aggregation boundaries, Explorer count reconciliation, scope/date forwarding, empty/error states, navigation/persona behavior, both provider builds, storage contracts and the compiled No-SQL browser smoke. Report validation covers scope/date rejection, projection-to-report count agreement, timestamps, empty data, long-label pagination and rendered page geometry, plus compiled download/error/retry/keyboard/narrow-layout checks. The existing Explorer continues to provide filtered Excel export.

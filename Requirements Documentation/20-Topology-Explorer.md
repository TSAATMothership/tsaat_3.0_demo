# Topology Explorer

Discovery includes **Topology Explorer** immediately below Shadow IT Explorer at `/discovery-coverage?discoveryView=topology`. Header network/ICT-system scope, security domains, selected snapshot and persona page visibility apply. No header scope means no topology load. Existing saved persona selections remain intact; the new page appears in the configurable catalogue and default all-enabled personas.

## CI lookup

Search covers endpoint CIs (including unidentified IP nodes), ICT systems, managed networks, business services and mission capabilities. Five menus reuse the exact FilterHeader component from End Point Explorer table headers: CI name or ID, Installed software, CVE code, IP address and CI type. Each menu provides a case-insensitive search of available values, checkbox multi-selection, matching-CI counts, Clear filter and Select matches. Typing searches menu options; checking values applies exact matches immediately. Selections combine with OR within a field and AND across fields. Name choices include the recorded name, CI ID and distinct hostname. CI type retains the five topology categories. Counts respect all other lookup fields and count a CI once per value, even when evidence is repeated. Active filter chips support individual removal; Clear filters resets every lookup field while retaining the graph root. Missing endpoint evidence appears as Not recorded; model CIs never appear in endpoint-evidence facets. Software, CVE and IP fields match recorded endpoint evidence only; they do not imply that a model CI itself has installed software. Results include CIs with no findings and are paginated, without truncating the searchable inventory. Blank software/IP/CVE evidence never invents a match.

The full, resolved snapshot supplies inventory, software and vulnerability observations through `lib/data-loader.ts`. Lookup and graph use the same snapshot. Security domains filter each endpoint, network and system independently; service/capability entries are derived only from allowed systems. Multiple environment memberships and the endpoint system context retain all recorded in-scope associations. ARP nodes can be found in an owner's selected system scope, consistent with Shadow IT, but the relationship stays labelled **observed in ARP table** rather than fabricated system membership. Unassigned-network placeholders are excluded.

## Graph meaning

The page reuses Impact Topology layouts and animation, category colours, node inspection, dragging, pan, zoom and Fit graph. Initial layout is hierarchical. Force-directed and radial layouts are available; force layout is disabled above 140 nodes to avoid quadratic work. Every path node and edge remains available; the graph does not silently truncate the path.

Two keyboard-accessible WorkspaceTabs in the Impact Topology header control the graph: **Business Impact** (default) and **Dependencies**. There is no separate mode row above the Matching CIs/graph panels. The tabs are available before selecting a CI and inside full screen. Changing modes retains lookup filters, the starting CI, header scope and snapshot; the graph resets its layout/camera/inspection for the changed paths while remaining in full screen if expanded.

| Mode / selected CI | Paths displayed |
| --- | --- |
| Business Impact / Endpoint CI | Recorded model ancestors: networks, systems, business services and mission capabilities. ARP ownership remains an observation; sibling endpoints and communication peers are excluded. |
| Business Impact / Model CI | Descendant systems/networks of the selected service, capability, system or network, plus their model ancestors and service/capability context. Ancestors never seed expansion into unrelated sibling branches. Endpoint inventory is not expanded. |
| Dependencies / Endpoint CI | Direct incoming and outgoing Flow Dependency observations, plus recorded model ancestors of the starting CI and each peer. Peers can be outside the selected network/system, but every endpoint and context model independently respects Security Domain filtering. |
| Dependencies / Model CI | Communication involving its recorded member endpoints within the header scope, including both internal flows and direct external peers, with the model context of every participant. The mode does not claim that a service or network itself sends packets. |

Links preserve their labels and direction: service/capability **depends on** system, network **hosts** system, model **contains CI**, explicit parent **contains system/network**, and ARP observer **observed in ARP table**. Tracing upstream follows these arrows in reverse; downstream system paths include their hosting networks as context. Services and capabilities both associate directly with recorded systems; the page does not invent a mission-to-service relationship from co-occurrence. Cycles and duplicate associations terminate/deduplicate safely.

Communication arrows retain recorded source-to-target direction. Multiple observations for one directed pair share one curved cyan dashed edge; the reverse direction remains a separate curve. Grey edges retain model/ARP labels. The paginated, filterable Communication evidence table exposes source, target, protocol, both ports, observation method and UTC observation time. Logical Dependency declarations and ARP observations do not establish communication and never produce flow arrows. Unknown evidence fields display Not recorded; future-dated observations beyond the selected snapshot day, missing endpoints and self-links are excluded. Exact duplicate observations are deduplicated. Peers never seed a second communication hop, and ancestor networks never expand unrelated endpoint siblings.

Lookup remains header-scoped in both modes. Dependencies preloads only direct peers of scoped endpoints and their domain-permitted ancestors, using the same resolved full snapshot. External context nodes have dashed outlines, accessible outside-scope labels and an inspector notice. **Explore in this CI’s scope** explicitly opens that CI's network/associated systems, retaining mode, domains and the resolved snapshot. External-peer CMDB Explore Topology uses the peer network as well. Viewing/inspecting a peer alone does not change header scope. Missing flows show a distinct no-recorded-communication notice with available business context; this is not proof of no dependency. Findings/severity filters do not hide topology. These views do not simulate outages.

Selecting a graph node inspects it without changing the starting CI or camera. **Explore from this CI** starts a new trace in the selected mode for a CI already in lookup scope. CMDB uses the existing mapped, persona-controlled popup. The expandable path evidence uses FindingsDataTable for every included CI, followed by exact labelled relationships.

Every CMDB popup includes **Explore Topology**. Once CI details load, it opens this page with that exact CI selected, retaining the originating network/system and security-domain scope and pinning the resolved CMDB snapshot. Without a header scope it uses an endpoint's recorded network or a model CI's related systems. Unrelated explorer filters and old topology lookup/selection parameters are dropped. The action is disabled while details are loading/unavailable or Topology Explorer is disabled for the active persona. Document navigation clears stacked popups and initializes the new root even when launched from Topology Explorer itself.

## Interaction and state

The node inspector offers CMDB drill-through for endpoint CIs, Business Services and Mission Capabilities in both modes, inline and full screen. Model CI details use recorded identity/criticality and scoped associations, through the same native slide-out panel and persona permission. Closing it returns to the invoking link without changing the graph view. Its Explore Topology action retains model identity, scope, mode and resolved snapshot. See [model CI mapping and upgrade](../docs/cmdb-asset-type-attributes.md).

Scrolling the mouse wheel over the canvas zooms in (up) or out (down), in both modes and inline/full-screen views. It uses the existing 30–600% zoom range and retains pan, node selection and moved nodes. Handled vertical wheel events do not scroll the page/workspace, including at zoom limits. Scrolling outside the canvas remains normal; horizontal-only and Ctrl/Meta wheel are left to the browser. Buttons, keyboard zoom and Fit graph remain available.

Layout and navigation use a slim toolbar without a separate card heading: the labelled layout selector, zoom controls, percentage and Fit graph share one row when space permits and wrap into two on narrow panels. The same controls remain visible in full screen, with native keyboard operation and visible focus.

When Matching CIs and Impact Topology appear side by side, both panels share a 44rem height, including their headings and controls. The results list and graph workspace scroll internally so filtering, pagination and long inspector details do not change the aligned panel edges. On phones the panels stack and retain independent content heights, including the taller compact graph layout.

**Full screen** in the graph header opens a native modal covering the application viewport. **Exit full screen** or Escape restores the inline graph and returns focus to the toggle. The selected root/mode, lookup/scope/date, layout, zoom/pan, moved nodes, graph search and inspected node are retained. The underlying page is inactive while expanded; keyboard focus stays within the modal. Nested CMDB popups remain usable and close before the graph on Escape. No new persona popup permission is introduced because this is an alternate presentation of the same permitted page.

`topologyMode=dependencies` persists the selected graph mode; omitted, unknown and legacy mode values use Business Impact. Mode tabs support Left/Right, Home/End and visible focus. Same-page CMDB navigation retains Dependencies while replacing the root and clearing lookup filters. Other CMDB entry points use Business Impact. Retry preserves mode and both current/legacy lookup parameters.

Multi-selections persist in validated `topology_filters` JSON and the starting CI stays in `topologyCi`. CI-name selections store stable node IDs to keep bookmarks compact and retain identity across display-name changes; the shared filter's optional label formatter displays and searches names, source IDs and hostnames. Other consumers retain their existing raw-value labels. Legacy `topology_name`, `topology_software`, `topology_cve`, `topology_ip` and `topology_kind` bookmarks retain their original partial-match/category behavior and appear as removable search chips. A menu change replaces that field's legacy search; Clear filter removes both forms for its field. Reload retains selections, scope and snapshot. Values unavailable after a scope change remain selected with zero counts until cleared. Scope/snapshot changes rebuild the graph; a stale or out-of-scope starting CI shows an explicit unavailable state. Errors reveal no database details, preserve scope/lookup on Retry and complete the route-ready loading state.

Filter menus share the Explorer popup placement, search focus, Escape/close focus return and outside-click dismissal. Menus fit narrow viewports and expose choices without relying on hover. Result and graph nodes support Enter/Space. Focus the canvas for arrow-key pan, plus/minus zoom and 0 to fit. Nodes and background support pointer dragging. Layout animation respects reduced motion. Mobile stacks filters, a bounded results list and the graph without page-wide horizontal overflow; every control has a visible focus state.

## Data and validation boundary

The inline Impact Topology uses the Service Impact Analyser's shared SVG node presentation and graph styles: category-coloured discs, selection halos, relationship labels, dotted canvas, summary strip and searchable connected-node inspector. Its compact layout/navigation toolbar retains the same control styling. Topology badges count distinct connected CIs in the displayed graph, not findings; neutral halos make no severity claim. A separate outer ring marks the starting CI and dashed disc outlines identify external context. Communication curves retain their cyan dashed direction arrows. Inspection/search highlights connections without changing the starting CI, graph membership, header scope or camera. The inspector sits beside the canvas when space permits and stacks below it in narrower graph panels; compact hierarchical labels retain their two-line layout.

Presentation-only changes use focused topology/shared-graph regressions, lint/types and compiled browser/keyboard/narrow-layout checks for both graph surfaces. They do not require provider/storage gates unless data or tracing behavior changes.

`lib/topology-explorer-data.ts` loads one full snapshot through the common facade; `lib/topology-explorer.ts` projects scoped nodes/relationships and lookups for both providers. Existing SQL/JSON full readers already supply the necessary membership, inventory and hierarchy fields. No new provider operation, schema, stored record, calculation rule, checksum, seed or migration is required. Existing JSON stores are preserved during builds. No dependency or offline asset changes are introduced.

The original feature selected validation: focused lookup/trace/scope/loader/route/render tests and impact-layout/persona regressions; lint/types; storage/evidence checks; both offline-guarded builds; shared compiled browser checks and full No-SQL smoke; real SQL/JSON model parity across historical dates and network/system/domain scopes on an explicitly disposable database. Navigation inventories and affected docs are regenerated/checked. Report formats, dependency installation and release certification are unaffected.

The header-filter presentation update uses `lib/topology-lookup-filters.ts` over the existing scoped nodes. The graph modes additionally use existing full-snapshot `ciDependencies` from SQL's `ci_dependency` records and JSON's snapshot collection. No SQL migration or JSON upgrade is required. Mode/context changes require scoped tracing and evidence regressions, both guarded builds, storage/evidence checks, compiled No-SQL smoke and historical/domain SQL/JSON parity on an explicitly disposable database. See [context decision](../docs/adr/0020-topology-modes-and-context.md) and [validation records](../docs/validation.md).

# Topology Explorer

Discovery includes **Topology Explorer** immediately below Shadow IT Explorer at `/discovery-coverage?discoveryView=topology`. Header network/ICT-system scope, security domains, selected snapshot and persona page visibility apply. No header scope means no topology load. Existing saved persona selections remain intact; the new page appears in the configurable catalogue and default all-enabled personas.

## CI lookup

The mission model category is displayed as **Mission Service**, with the **MS** graph glyph. Existing `mission:` node IDs, `mission-capability` CMDB requests and SQL/JSON relationship fields remain compatible. Saved CI-type filters using the former Mission Capability or Mission System labels resolve to Mission Service.

Search covers endpoint CIs (including unidentified IP nodes), ICT systems, managed networks, business services and mission services. Five menus reuse the exact FilterHeader component from End Point Explorer table headers: CI name or ID, Installed software, CVE code, IP address and CI type. Each menu provides a case-insensitive search of available values, checkbox multi-selection, matching-CI counts, Clear filter and Select matches. Typing searches menu options; checking values applies exact matches immediately. Selections combine with OR within a field and AND across fields. Name choices include the recorded name, CI ID and distinct hostname. CI type retains the five topology categories. Counts respect all other lookup fields and count a CI once per value, even when evidence is repeated. Active filter chips support individual removal; Clear filters resets every lookup field while retaining the graph root. Missing endpoint evidence appears as Not recorded; model CIs never appear in endpoint-evidence facets. Software, CVE and IP fields match recorded endpoint evidence only; they do not imply that a model CI itself has installed software. Results include CIs with no findings and are paginated, without truncating the searchable inventory. Blank software/IP/CVE evidence never invents a match.

The resolved snapshot supplies scoped inventory, software and vulnerability observations through `lib/data-loader.ts`. The focused read omits unrelated discovery evaluation and unused CI communication rows. Lookup and graph use the same snapshot. Security domains filter each endpoint, network and system independently; service/mission-service entries are derived only from allowed systems. Multiple environment memberships and the endpoint system context retain all recorded in-scope associations. ARP nodes can be found in an owner's selected system scope, consistent with Shadow IT, but the relationship stays labelled **observed in ARP table** rather than fabricated system membership. Unassigned-network placeholders are excluded.

## Graph meaning

The page reuses Impact Topology layouts and animation, category colours, node inspection, dragging, pan, zoom and Fit graph. Initial layout is hierarchical. Force-directed and radial layouts are available; force layout is disabled above 140 nodes to avoid quadratic work. Every path node and edge remains available; the graph does not silently truncate the path.

Two keyboard-accessible WorkspaceTabs in the Impact Topology header control the graph: **Business Impact** (default) and **Dependencies**. There is no separate mode row above the Matching CIs/graph panels. The tabs are available before selecting a CI and inside full screen. Changing modes retains lookup filters, the starting CI, header scope and snapshot; the graph resets its layout/camera/inspection for the changed paths while remaining in full screen if expanded.

| Mode / selected CI | Paths displayed |
| --- | --- |
| Business Impact / Endpoint CI | Recorded model ancestors: networks, systems, business services and mission services. ARP ownership remains an observation; sibling endpoints and communication peers are excluded. |
| Business Impact / Model CI | Descendant systems/networks of the selected business service, mission service, ICT system or network, plus their model ancestors and service/mission-service context. Ancestors never seed expansion into unrelated sibling branches. Endpoint inventory is not expanded. |
| Dependencies / Endpoint CI | Recorded network/system memberships and their model ancestors, including business services and mission services. CI-to-CI links and ARP observations are excluded. |
| Dependencies / Model CI | Recorded descendant networks/systems and their member endpoint CIs, followed by model ancestors of those descendants. Context networks and shared systems never expand unrelated sibling branches. |

Links preserve their labels and direction: service/mission-service **depends on** system, network **hosts** system, model **contains CI**, explicit parent **contains system/network**, and ARP observer **observed in ARP table**. Tracing upstream follows these arrows in reverse; downstream system paths include their hosting networks as context. Business services and mission services both associate directly with recorded systems; the page does not invent a mission-to-service relationship from co-occurrence. Cycles and duplicate associations terminate/deduplicate safely.

Dependencies uses hosting, membership, association and explicit hierarchy edges only. Both Flow Dependency and Logical Dependency records are endpoint-to-endpoint links and are excluded entirely. ARP observations remain labelled Business Impact context only; they cannot assign system membership or expand Dependencies.

The paginated, filterable Relationship evidence table exposes source CI, relationship label, target CI and environment. System membership combines environment asset lists and endpoint system context, retaining all recorded in-scope systems and deduplicating environment types for each system/CI pair. Environment shows Not applicable for other relationship kinds and Not recorded when applicable evidence is missing. The graph summary counts recorded relationships and member endpoints. Network CIs without system membership remain visible when tracing their network.

Lookup and both graphs retain the header network/system scope, independently applied Security Domains and resolved snapshot. No communication peers are loaded into the graph outside that scope. Missing relationships show an explicit no-recorded-paths state; they do not prove absence of a real dependency. Findings/severity filters do not hide topology. These views do not simulate outages.

Selecting a graph node inspects it without changing the starting CI or camera. **Explore from this CI** starts a new trace in the selected mode for a CI already in lookup scope. CMDB uses the existing mapped, persona-controlled popup. The expandable path evidence uses FindingsDataTable for every included CI, followed by exact labelled relationships.

In-scope Explore actions are buttons that change the current trace without reloading the document or changing header scope.

Every CMDB popup includes **Explore Topology**. Once CI details load, it opens this page with that exact CI selected, retaining the originating network/system and security-domain scope and pinning the resolved CMDB snapshot. Without a header scope it uses an endpoint's recorded network or a model CI's related systems. Unrelated explorer filters and old topology lookup/selection parameters are dropped. The action is disabled while details are loading/unavailable or Topology Explorer is disabled for the active persona. Document navigation clears stacked popups and initializes the new root even when launched from Topology Explorer itself.

## Interaction and state

The node inspector offers CMDB drill-through for endpoint CIs, Business Services and Mission Services in both modes, inline and full screen. Model CI details use recorded identity/criticality and scoped associations, through the same native slide-out panel and persona permission. Closing it returns to the invoking link without changing the graph view. Its Explore Topology action retains model identity, scope, mode and resolved snapshot. See [model CI mapping and upgrade](../docs/cmdb-asset-type-attributes.md).

Scrolling the mouse wheel over the canvas zooms in (up) or out (down), in both modes and inline/full-screen views. It uses the existing 30–600% zoom range and retains pan, node selection and moved nodes. Handled vertical wheel events do not scroll the page/workspace, including at zoom limits. Scrolling outside the canvas remains normal; horizontal-only and Ctrl/Meta wheel are left to the browser. Buttons, keyboard zoom and Fit graph remain available.

Layout and navigation use a slim toolbar without a separate card heading: the labelled layout selector, zoom controls, percentage and Fit graph share one row when space permits and wrap into two on narrow panels. The same controls remain visible in full screen, with native keyboard operation and visible focus.

When Matching CIs and Impact Topology appear side by side, both panels share a 44rem height, including their headings and controls. The results list and graph workspace scroll internally so filtering, pagination and long inspector details do not change the aligned panel edges. On phones the panels stack and retain independent content heights, including the taller compact graph layout.

**Full screen** in the graph header opens a native modal covering the application viewport. **Exit full screen** or Escape restores the inline graph and returns focus to the toggle. The selected root/mode, lookup/scope/date, layout, zoom/pan, moved nodes, graph search and inspected node are retained. The underlying page is inactive while expanded; keyboard focus stays within the modal. Nested CMDB popups remain usable and close before the graph on Escape. No new persona popup permission is introduced because this is an alternate presentation of the same permitted page.

`topologyMode=dependencies` persists the selected graph mode; omitted, unknown and legacy mode values use Business Impact. Mode tabs support Left/Right, Home/End and visible focus. Same-page CMDB navigation retains Dependencies while replacing the root and clearing lookup filters. Other CMDB entry points use Business Impact. Retry preserves mode and both current/legacy lookup parameters.

Multi-selections persist in validated `topology_filters` JSON and the starting CI stays in `topologyCi`. CI-name selections store stable node IDs to keep bookmarks compact and retain identity across display-name changes; the shared filter's optional label formatter displays and searches names, source IDs and hostnames. Other consumers retain their existing raw-value labels. Legacy `topology_name`, `topology_software`, `topology_cve`, `topology_ip` and `topology_kind` bookmarks retain their original partial-match/category behavior and appear as removable search chips. A menu change replaces that field's legacy search; Clear filter removes both forms for its field. Reload retains selections, scope and snapshot. Values unavailable after a scope change remain selected with zero counts until cleared. Scope/snapshot changes rebuild the graph; a stale or out-of-scope starting CI shows an explicit unavailable state. Errors reveal no database details, preserve scope/lookup on Retry and complete the route-ready loading state.

Filter menus share the Explorer popup placement, search focus, Escape/close focus return and outside-click dismissal. Menus fit narrow viewports and expose choices without relying on hover. Result and graph nodes support Enter/Space. Focus the canvas for arrow-key pan, plus/minus zoom and 0 to fit. Nodes and background support pointer dragging. Layout animation respects reduced motion. Mobile stacks filters, a bounded results list and the graph without page-wide horizontal overflow; every control has a visible focus state.

## Data and validation boundary

**Show all results in Impact Topology** selects every matching CI across result pages. It retains header scope, snapshot and mode, deduplicates shared context and follows lookup changes while active. `topologyAll=1` persists this selection; choosing an individual CI restores single-result behavior. Every starting CI has an outer ring. Empty matches show explicit guidance and disable all-results/export actions.

**Generate Impact Report** exports the presented graph as PDF, preserving selection, filters, scope/date, mode, layout and node positions. It includes an executive brief and category graphics, the full fitted topology, a model/service view, service narratives, analyst CVE/evidence-gap review and complete CI, relationship and software registers. Counts describe the graph and do not predict outages or infer exploitation/severity. The shared worker provides progress/cancel/retry, duplicate prevention and focus return, including in full screen. Pagination does not truncate either graph or report. See the [report contract](../docs/topology-impact-report.md).

The inline Impact Topology uses the retained shared SVG node presentation and graph styles: category-coloured discs, selection halos, relationship labels, dotted canvas, summary strip and searchable connected-node inspector. Its compact layout/navigation toolbar retains the same control styling. Topology badges count distinct connected CIs in the displayed graph, not findings; neutral halos make no severity claim. A separate outer ring marks the starting CI; arrows retain recorded model relationship labels. Inspection/search highlights connections without changing the starting CI, graph membership, header scope or camera. The inspector sits beside the canvas when space permits and stacks below it in narrower graph panels; compact hierarchical labels retain their two-line layout.

Presentation-only changes use focused topology/shared-graph regressions, lint/types and compiled browser/keyboard/narrow-layout checks for both graph surfaces. They do not require provider/storage gates unless data or tracing behavior changes.

`lib/topology-explorer-data.ts` loads one scoped detail projection through the common facade; `lib/topology-explorer.ts` projects scoped nodes/relationships and lookups for both providers. Both SQL/JSON detail readers retain the necessary membership, inventory and hierarchy fields, including ARP owners needed for scope context. The focused operation has complete-snapshot equivalence and cross-provider parity coverage. No schema, stored record, calculation rule, seed or migration changes are required. Existing JSON stores are preserved during builds. No dependency or offline asset changes are introduced.

The original feature selected validation: focused lookup/trace/scope/loader/route/render tests and impact-layout/persona regressions; lint/types; storage/evidence checks; both offline-guarded builds; shared compiled browser checks and full No-SQL smoke; real SQL/JSON model parity across historical dates and network/system/domain scopes on an explicitly disposable database. Navigation inventories and affected docs are regenerated/checked. Report formats, dependency installation and release certification are unaffected.

The header-filter presentation uses `lib/topology-lookup-filters.ts` over existing scoped nodes. Dependencies now uses recorded model relationships, not the snapshot's `ciDependencies` collection. CI communication remains stored in SQL and JSON for a future separate feature. No SQL migration, JSON upgrade, evidence rewrite or checksum change is required. Mode/tracing changes require scoped regressions, both guarded builds, storage/evidence checks, compiled No-SQL smoke and historical/domain SQL/JSON parity on an explicitly disposable database. See [model relationship decision](../docs/adr/0031-topology-model-dependencies.md) and [validation records](../docs/validation.md).

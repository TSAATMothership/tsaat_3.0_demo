# Workspace, navigation and scope

Header controls retain their compact original styling and natural wrapping, with controls on each row vertically centred. Persona keeps its native select and cyan divider, scope filters keep their existing boxes, and Date remains unboxed. Scope dropdowns remain inside the viewport on resize, scroll when height is limited and restore trigger focus on Escape. Alignment preserves scope staging, Update, snapshot selection and native keyboard controls.

Persona selection is available directly in the header, including All sections and load/retry recovery. Stored definitions remain read-only. Browser-local selection preserves route, scope, security domains and snapshot date; saved preferences still filter navigation and popup actions. Menu and Settings are retired. Existing /settings URLs provide a scoped retirement page; direct page/API access keeps the current model. See [Personas](../docs/personas.md).

Current contract: TSAAT UI 3 baseline, 2026-11-03. Maintain with related source changes; see [SDLC](../docs/sdlc.md).

Pages and APIs open directly without user login. The header has no Signed in or Logout controls. The initial workspace stays empty until a sidebar page is selected. If that retained page has neither a managed-network nor ICT-system selection, the workspace presents an illustrated notice advising selection of at least one entity and Update. Two actions open the corresponding header selectors with keyboard focus; on narrow screens sidebar selection reveals the workspace. The two scope types are mutually exclusive, accept multiple IDs and retain the selected snapshot date. Pending header edits are applied with Update; navigating away discards unapplied edits. Clearing the last applied selection restores the notice while retaining the active item. A selected scope with zero matching records retains its page-specific empty result state.

Sidebar order and visibility are defined in lib/workspace-navigation.ts. Governance is first, with Trends, Cyber Terrain Insights, Installed Software Insights, Discovery Insights, End Point Insights and Security Vulnerability Insights, in that order. Security Vulnerability Insights uses `/governance/security-vulnerability-insights` to explain observations, missing metadata, sources and discovery coverage. End Point Insights uses `/governance/end-point-insights` and explains the endpoint inventory, missing fields, discovery evidence and tool coverage. Discovery Insights uses `/governance/discovery-insights`; legacy `discoveryView=overview` links redirect there with scope/date retained. Governance Overview is retired; `/governance/overview` redirects to Trends while preserving query selections, including header scope, security domains and date. Trends presents a scoped executive history of compliance, lifecycle and discovery. Cyber Terrain Insights is a scrolling [executive briefing](15-Governance-Insights.md) using existing scoped Discovery and Service Impact data. Without scope the content remains empty. All six remain available under either scope kind and retain scope/date during navigation. No new API or storage contract is introduced.

Cyber Security follows Governance with Network Risk Profile then ICT System Risk Profile, followed by Service Impact Analyser, ICT System Impact Analyser and ICT System Dependencies. Discovery contains coverage and inventory explorers, with Installed Software Explorer; Installed Software Dashboard is omitted from the sidebar while its bookmarked URL remains available. Installed Software Insights is a separate Governance page directly below Cyber Terrain Insights. Topology Explorer follows Shadow IT Explorer in Discovery and uses the same scope/date. Observed Measures starts with Measures Summary, followed by Measures Trends, KPIs and SPIs. Measures Trends separates KPI/SPI history into two tabs with five date ranges. Findings contains only Findings Register; Briefs & Reports is separate. Menu and Settings are retired; the existing persona selector is in the header. The Cyber COP overview, old posture pages, entity/SPI heatmaps, Findings Summary and Target State Analyser are not sidebar destinations.

Navigation preserves applied scope/date. Known workspace destinations with no network/system scope show the notice without a loading animation; the empty landing page also skips that animation. Header date/domain changes without an applied entity scope and clearing the last entity selection follow the same rule. Scoped data navigation displays the shared loading overlay until route readiness and supports cancellation to the previous view. Retired posture and entity URLs redirect to current risk profiles/details rather than rendering the previous page design.

Every collapsible sidebar section starts collapsed when the workspace loads, including direct bookmarks and page reloads. Section buttons expand/collapse their own links with mouse, Enter or Space and expose the current state through aria-expanded. User-opened sections remain open during client-side navigation. The sidebar itself starts visible, and the standalone Briefs & Reports link remains available.

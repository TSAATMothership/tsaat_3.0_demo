# Cyber Security and impact analysers

Current contract: TSAAT UI 3 baseline, 2026-11-02. Maintain with related source changes; see [SDLC](../docs/sdlc.md).

Visible entrypoints are the two risk profiles, Service Impact Analyser, ICT System Impact Analyser and ICT System Dependencies. app/cyber-cop/page.tsx selects the analyser via copView. The overview value remains a compatibility route, not a sidebar page.

Service Impact keeps Scope & Selection on the page; the Explore the Impact tab is removed. Explore selection opens a native, Settings-sized Impact graph popup using the current header scope/domains/snapshot, service/capability filters, ICT table filters and selected systems. With no checked systems, all matching system rows are used; zero matching rows remain empty. The explicit critical/high focus selects systems with severe findings and retains all open findings within those systems. Closing the popup preserves the tables and returns focus to Explore selection.

The graph connects business services and mission capabilities to ICT systems (depends on), and systems to affected CIs (contains), using recorded associations only. Category colours, critical/high risk rings and finding-count badges support inspection. Node details, search, system expansion, connection focus, draggable nodes, pan, zoom and Fit graph support exploration. Selecting a node by pointer, keyboard, search result or connected-node link retains the current camera zoom and pan; Fit graph and the 0 key still reset the view explicitly. No predicted outage or additional dependency is inferred. Shared entities can contain the same findings; summary findings/CIs are deduplicated. Systems without findings remain available with All systems and a zero minimum; zero findings does not establish compliance.

Dynamic risk filters use configured severity keys/labels, including unfamiliar observed keys. Critical Exposure and High Risk start selected with a 1-to-maximum count range. Reset filters restores those defaults. Selecting a severity subset resets the range to 1-to-maximum so only nodes with matching findings appear; users can explicitly choose Min 0. Select all selects every available severity with a 0-to-maximum range. Selecting no severities stays empty. The inclusive Min/Max sliders and number fields count the combined findings in the selected severities for each node. Search, node badges, details and summary totals follow both filters. Edges appear only when both endpoints match; filtering never restores hidden neighbours. Matching devices whose parent system is excluded by the filters appear directly, subject to scene limits. Totals include all matching nodes, including collapsed ones, with shared findings deduplicated; scene focus/layout/render limits do not alter them. Reset risk filters restores the initial values without changing the page's header or table selection. Escape closes the severity menu before the dialog.

Hierarchical with Top down is the default layout whenever the popup opens. Force-Directed remains available with bounded gravity, repulsion and edge springs (recorded associations have unit weight). Hierarchical groups services/capabilities, systems and devices into directed tiers with left-to-right, right-to-left, top-down and bottom-up options; wide tiers wrap into bands while keeping every source before its children. Circular / Radial offers a single circle or concentric rings for a well-connected hub, its immediate neighbours, remaining connected nodes and disconnected nodes. Coordinate / Spatial generates repeatable custom X/Y positions from the complete scoped graph before risk/scene filtering; these remain stable through filtering and expansion. Dragging or editing a node's X/Y changes its popup-session coordinates; switching layouts preserves them, Reset coordinates restores generated values, and closing the popup discards edits. These are workspace coordinates, not geographic locations. Layout changes tween nodes, edges and viewport bounds together over 650ms, cancel/restart from the current frame on rapid changes, and skip animation for prefers-reduced-motion. All layouts use local code and assets; no new dependencies, data fields, provider operations or persistence are required.

Controls are grouped into Filters (Risk severity, aligned Min/Max fields and sliders, Reset filters) and Layout & view (layout/direction/arrangement, coordinates reset, zoom and Fit graph). Focus connections / Show scope sits at the top-right of the graph canvas, stays anchored during pan/zoom and is disabled until a node is selected. Groups align side by side on wide windows and stack on narrower windows. Findings per node identifies the selected severity labels and their observed maximum. One severity projection supplies range bounds, node counts, finding rows and filtered summaries. Badges show exact matching counts, including values above 99; node details show the selected severity breakdown, and dropdown option counts are labelled as scope-wide findings. Clearing all severities disables the count controls and keeps the graph empty. A selected category with no observations retains the positive minimum; explicitly choosing zero still includes zero-count nodes.

Scenes initially expand affected CIs when there are at most 12; larger scopes start with services/capabilities/systems and expand on demand. Rendering is bounded to 140 nodes with explicit counts for omitted nodes; search/inspection use the complete scoped graph. Search results show up to 50 matches and request a narrower search when needed. Empty scopes, keyboard node selection, keyboard pan/zoom, Escape/focus return and narrow layouts are supported. Node and summary actions retain the Findings, Affected CIs, High-risk CVEs and Finding duration detail tabs. This presentation uses the existing shared model in SQL and JSON builds; no provider/schema or stored-data changes are required.

Filters includes an Expand all affected CIs toggle below Risk severity. It expands all scoped systems' affected CIs; pressing it again collapses those groups. Its pressed state also follows individual system expansion. Both actions clear node selection and connection focus and fit the scene, while preserving severity/count filters, layout and analysis totals. The toggle is disabled when no CIs match. Existing scene limits and the visibility of matching CIs whose parents are filtered out still apply.

Device links in Service Impact finding details open CMDB above the existing graph/findings dialogs, without closing the findings panel. The active findings tab, search/filters, scroll and expanded evidence stay mounted. CMDB slides from the left and is 20% narrower than its former width: min(44.8rem, 76.8vw). Closing CMDB or pressing Escape returns focus to the invoking device; findings and the graph remain open. The top dialog owns keyboard focus and Escape, including CMDB loading/error/Retry states.

ICT System Dependencies is a standalone sidebar entry immediately below ICT System Impact Analyser, using copView=ict-system-dependencies. It retains header system/network scope, security domains and the selected snapshot. Its system selector includes all scoped ICT systems, including systems without open findings; select systems and Run to load the existing dependency API. The former in-analyser dependency overlay/button is removed. Environment starts at Production, remains explicit even when there are no matching rows and can be changed to other environments or All. The directed six-axis diagram, filtered Excel export and server CMDB/compliance actions remain available. Empty, loading, error/Retry and keyboard behavior apply independently of the risk analyser.

ICT System Impact Analyser starts with Critical Exposure and High Risk selected in Findings Severity. Users can choose other severities or All; a new run starts with the defaults. These defaults do not change dependency results. This is a navigation/presentation change using existing shared provider operations; no SQL/JSON format, data, migration or calculation-contract update is needed.

ICT impact and dependency diagrams are run-gated and use lazy data APIs, worker filtering and scalable Canvas/WebGL rendering. Source/related asset metadata, directed modeled relationships and the active snapshot determine diagram scope. Selecting an eligible asset exposes separate CMDB and compliance actions.

Network Impact Analyser is retired: its sidebar item, run panel and CMDB launch button are removed. Existing copView=network-impact-analyser bookmarks redirect to the matching network/ICT-system risk profile with applied header scope, security domains and snapshot date retained; analyser-only parameters are dropped. The redirect also handles empty scope without loading analyser data. Existing shared/network analyser data APIs remain available for compatibility, with their current scope and exact asset-ID restrictions. No SQL/JSON data, schema, calculations or package changes are required.

The shared asset compliance view uses the native settings-popup dimensions. Security Posture, Findings and Discovery Coverage tabs use the standard table controls. SPIs start with lowest compliance; result pills have equal widths. Summary bars show compliance/non-compliance/unknown and a numeric percentage, with N/A for no scored data. Discovery score excludes unavailable values from its denominator, as explained in the UI. Findings support priority, severity, workflow, timestamp and numeric Duration filters/sorts. Expanded findings show evidence/remediation. SPI details expose evaluation evidence and all reasons. Discovery rows retain tool value, owner and operations manager.

Escape closes table menus before SPI detail and the outer modal; focus returns to its trigger. Search persists across normal tabs. Count shortcuts open the appropriate scope. Loading, abort, retry and empty states do not fabricate compliance.

TSAAT inventory storage v2
=========================

The tsaat schema stores eight-week bundled sample evidence or the installation's own historical inventory: dataset_snapshot, network/system hierarchy, assets, OS/network OS/patch level, installed software, vulnerabilities, discovery observations, environments/memberships, business services, mission capabilities and directed CI dependency edges.

Composite snapshot keys preserve historical relationships. Nullable and inapplicable fields retain their meaning. Discovery coverage rules and discovery/persona settings revisions remain. CMDB definitions/type mappings control presentation without replacing typed inventory. storage_schema_version marks version 2.

Findings, KPI/SPI definitions/evaluations/history, matrices, tasking/report metadata, server patch analytics, target-state assets and obsolete OS version comparison fields are removed. See retired-storage-v2.json for the exact reviewed object/field inventory and docs/generated/database-catalogue.md for current columns, keys, indexes and routines.

Fresh creation uses database-schema.sql plus the build manifest's three fresh additions. Existing databases through 032 use migration 033 with a verified backup and exact target acknowledgement. JSON stores have the paired explicit v2 migration. Follow docs/feature-retirement.md; never run base DDL or seed loaders against existing operational data.

SQL runtime configuration remains Windows DPAPI protected in DB_config. Setup creates a dedicated SQL login with SSL disabled; advanced configuration preserves saved TLS/Strict policy. Credentials, installed data and compiled artifacts must not be committed.

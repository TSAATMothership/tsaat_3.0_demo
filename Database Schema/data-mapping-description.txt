TSAAT Database Data Mapping Description
======================================

Canonical Package Root
----------------------
- Database Schema/
  - database-schema.sql
  - migrations/*.sql
  - data/*.json
  - loaders/*.sql, *.ps1, *.cmd

Discovered Application Database Name
------------------------------------
- TSAAT
- Discovery rule used by loader:
  1) data/database-build-manifest.json.applicationDatabaseName
  2) fallback: schema name from database-schema.sql (CREATE SCHEMA [tsaat] -> TSAAT)

SQL Server Target
-----------------
- Server: configured in encrypted `DB_config` payload (`server`).
- Application database: configured in encrypted `DB_config` payload (`database`).
- Authentication:
  - Controlled by `authMode` in encrypted `DB_config` payload.
  - `authMode=trusted` => Windows trusted auth.
  - `authMode=sql` => SQL login via `userId` + `password`.
  - SSL controlled by `sslEnabled` + `sslType`.
  - `sslEnabled=false` => no SSL transport encryption.
  - `sslEnabled=true, sslType=strict` => SSL with strict certificate validation.
  - `sslEnabled=true, sslType=trust-server-certificate` => SSL with trusted server certificate mode.
- `CreateDB.cmd` and `compileApp.cmd` confirm encrypted `DB_config` before use.
- Unattended missing-file or undecryptable-file provisioning uses `TSAAT_DB_CONFIG_ASSUME_YES=true` plus complete `TSAAT_SQL_*` values to create/recreate encrypted `DB_config`; confirmed file values then drive loaders/compile scripts.
- Admin database for bootstrap: master
- Application schema: tsaat
- Application login credentials are not imported into SQL Server; they are created/updated in local encrypted repository root `logindetails`.

Database Load Modes
-------------------
- `ClientPayload` is the default load mode. The machine running `CreateDB.cmd` reads the local JSON artefacts, sends them as parameterized `NVARCHAR(MAX)` payload inserts over the SQL connection, and then maps payloads into relational tables with `OPENJSON`.
- `SqlServerFiles` preserves SQL Server-side file reads through `OPENROWSET(BULK...)`. `CreateDB.cmd` requires one SQL-server-visible UNC staging root, supplied interactively or through `TSAAT_SQL_SERVER_STAGING_UNC_ROOT`, copies the required package/snapshot JSON files into `package-data` and `snapshots` subfolders, and passes those derived roots to the loader.
- `ClientPayload` is preferred for remote SQL Server installs because SQL Server does not need filesystem access to the application repository.

Snapshots and domain entities:
- snapshot root:
  - generatedAt -> dataset_snapshot.generated_at
  - snapshotDate -> dataset_snapshot.snapshot_date
  - source_label = snapshot file name

- managedNetworks[]:
  - id,name,criticality,adfPlatform,enterprisePlatform,modellingStatus,classification,description,owner,supportEmail,serviceCatalogueUrl,diisId,atoNumber,apmNumber,diisUrl,grcUrl,discoveryStatus
    -> managed_network
  - if modellingStatus is omitted, the loader derives it from discoveryStatus: `Discovery Non Enabled` -> false, otherwise true
  - if diisId, atoNumber, or apmNumber is omitted, the loader derives deterministic values as `DIIS-NET-XXX`, `ATO-NET-XXX`, and `APM-NET-XXX`
  - parentNetworkId + childNetworkIds[] -> managed_network_hierarchy
  - ictSystemIds[] -> network_declared_system
  - assetIds[] -> network_declared_asset
  - targetStateAssets.<assetType>[] (name-only target records) -> network_target_state_asset

- ictSystems[]:
  - id,networkId,name,adfPlatform,enterprisePlatform,description,diisId,owner,supportEmail,serviceCatalogueUrl,atoNumber,apmNumber,diisUrl,grcUrl,modellingStatus,diisDefined,criticality,securityDomain
    -> ict_system
  - if diisId, atoNumber, or apmNumber is omitted, the loader derives deterministic values as `DIIS-SYS-XXX`, `ATO-SYS-XXX`, and `APM-SYS-XXX`
  - parentSystemId + childSystemIds[] -> ict_system_hierarchy
  - missionCapabilities[] -> system_mission_capability
  - businessServices[] -> system_business_service
  - environments[] -> system_environment
  - environments[].assetIds[] -> system_environment_asset

- assets[]:
  - id,name,hostname,ipAddress,type,networkId,securityDomain,systemContext.systemId,systemContext.environmentType,lifecycle.eolStatus,lifecycle.warrantyStatus
    -> asset
  - operatingSystem -> asset_operating_system
  - networkOs -> asset_network_os
  - patchState -> asset_patch_state
  - installedSoftware[] -> asset_installed_software (ordinal = array index + 1)
  - vulnerabilities[] -> asset_vulnerability

- ciDependencies[] (optional):
  - id,sourceAssetId,targetAssetId,dependencyType,protocol,sourcePort,targetPort,observationMethod,observedAt
    -> ci_dependency

- findings[]:
  - id,spiId,priorityRank,severity,complianceStatus,scope.networkId,scope.systemId,scope.environmentType,scope.assetId,title,evidence,recommendedAction,status,timestamp,closedTimestamp
    -> finding

Identity and deterministic key policy:
- reference_version_set.version_set_id = 1
- discovery_tools_settings_version.settings_version_id = 1
- measures_settings_version.settings_version_id = 1
- dataset_snapshot.snapshot_id = 1..8 mapped to week-01..week-08

Normalization rule applied for relational integrity:
- If ictSystems[].networkId is empty string, loader maps it to synthetic networkId `net-unassigned`.
- Loader inserts one synthetic managed_network row per snapshot:
  - network_id = `net-unassigned`
  - name = `Unassigned Systems`
  - modelling_status = 0
  - diis_id = `DIIS-NET-000`
  - ato_number = `ATO-NET-000`
  - apm_number = `APM-NET-000`
  - criticality = `Non-Critical`
  - discovery_status = `Discovery Non Enabled`
- If ciDependencies[] is absent for a snapshot, loader synthesizes deterministic dependency examples:
  - environment-level Logical Dependency chains
  - environment/network-level Flow Dependency links
  - links from modelled CIs to unmodelled CIs for Not Modelled scenarios

Validation Rules Applied by loader/validator
--------------------------------------------
- Exactly 8 dataset snapshots required
- At least 10 SPI definitions required; current seed preserves SPI 1..10 and future supported SPI IDs may be added
- At least 5 severity definitions required; current seed preserves Critical Exposure, High Risk, Major, Moderate, and Data Gap
- Non-empty asset, finding, discovery_tool, kpi_definition, finding_severity_definition, finding_priority_definition, SPI rule catalogue, SPI parameter schema, SPI outcome template, SPI report detail catalogue, SPI SQL calculation source/definition/evidence, SPI feature binding, SPI finding classification, spi_rule_parameter, SPI tasking metadata, measures_severity_matrix, and measures_priority_matrix tables required
- `tsaat.usp_evaluate_spi_snapshot` must return valid JSON evidence rows for the latest snapshot using the DB-backed SQL calculation definitions
- Non-empty network_target_state_asset table required
- Full row-count summary emitted after load
- Seed profile constraints validated in `scripts/validate-seed.ts`:
  - 70% of assets modelled to ICT systems, 30% left unmodelled
  - ICT systems map server assets only (no workstations/network devices)
  - Per-system server count bounded to 20..300, with most systems < 50
  - Discovery-enabled network target-state asset types must not produce discovery-missing rows
  - Flow dependency distribution per source CI:
    - 10% with 0 edges
    - 70% with 20..50 edges
    - 19% with 3..19 edges
    - 1% with 51..150 edges

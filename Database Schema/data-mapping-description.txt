TSAAT SQL/JSON retained-inventory mappings
========================================

Canonical sources are data/current.json, data/snapshots/week-01.json through week-08.json, Database Schema/data/database-build-manifest.json and its three declared configuration files. NoSQL/cmdb-attributes.json provides shared CMDB presentation mappings. Source JSON is sample material, not a live database export.

dataset_snapshot maps snapshotId/snapshotDate/generatedAt. Managed networks, ICT systems and assets retain stable IDs plus snapshot keys. Inventory child arrays map OS/network OS, patch state, installed software, vulnerabilities and discovery observations. Environment memberships, service/capability memberships and directed CI dependency edges preserve their scope and observed dates. SQL export and JSON import use the same retained contract and deliberate null/unknown/inapplicable values.

The exact SQL import mappings are in loaders/load-data.sql. Reverse mappings are in scripts/sql-export-datasets.mjs. lib/inventory-schema.mjs validates/project snapshots for both paths; lib/data-loader.ts and lib/cmdb-attribute-loader.ts are mandatory feature facades. Discovery rules/settings and persona settings are the only manifest configuration inputs. CMDB references are initialized separately from the reviewed shared mapping.

Retired fields/references/objects are enumerated in retired-storage-v2.json. Current inputs reject those fields rather than silently recreating unsupported data. The explicit SQL 033 and JSON v2 upgrade remove them from existing stores while preserving retained evidence and persona metadata. Fresh builds never replace installed JSON stores or seed SQL.

Validate the same explicitly selected dates, network/system/security-domain scopes and settings in both providers. Keep all eight bundled weekly snapshots, valid observation dates and applicable attributes. See docs/data-providers.md, docs/sample-evidence.md and docs/feature-retirement.md for import, upgrade, parity and recovery.
